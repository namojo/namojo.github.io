# 팩트 카드 — 2026-10-20

## 토픽
DeepSeek이 검색(Search)·페치(Fetch) API를 외부 개발자에게 공개. 성공 요청 1,000건당 0.75달러.

## 날짜·주체
- 발표: 2026-10-17 (DeepSeek 공식 X 계정 스레드, 4개 포스트 중 3번째)
- 주체: DeepSeek (중국). 빅테크 아님, 최근 7일 내 주 토픽으로 다룬 적 없음.

## 핵심 사실 (출처: DeepSeek 공식 API 문서 api-docs.deepseek.com/guides/search)
- 엔드포인트: POST api.deepseek.com/v1/tools/search , /v1/tools/fetch
- 가격: 각각 **성공 요청 1,000건당 $0.75**. 요청당 과금이며 결과 개수(count)는 가격에 영향 없음.
- 과금 조건: HTTP 200 + 결과가 있을 때만. 빈 결과·실패·타임아웃은 과금 안 함.
- Search 요청 필드: query(1~128자), count(1~50, 기본 10), ori_question(사용자 원 질문), localization(IP), need_content(bool, **기본 false**)
- Search 응답 필드: rerank_score(0~3), title, url, **snippet(약 100~200자, UI 표시용)**, **summary(약 600~800자, 모델이 읽는 용)**, **content(need_content=true일 때만, 아니면 빈 문자열)**, site_name, site_icon, date, authority(0~4, -1=불명)
- Fetch: url 1개 → title + content(마크다운). 한 호출당 한 페이지.
- QPS: Search 100, Fetch 25 (계정 단위, API 키 무관). Fetch는 도메인별 QPS 제한 추가(수치 미공개).
- 무료 기간: DeepSeek Harness / Claude Code / Codex를 통한 서버사이드 툴 호출은 **2026-11-01 00:00 베이징 시각(=10/31 16:00 UTC)**부터 과금 시작.
- 문서가 밝히지 않은 것: authority 등급 산정 방법, Fetch 크롤러의 User-Agent·IP 대역·robots.txt 준수 여부, ori_question·localization의 보관·이용 방식.

⚠ 2차 보도(ppc.land)는 QPS를 "5 req/s"로 적었으나 **공식 문서는 Search 100 / Fetch 25**. 공식 문서를 따른다.

## 토큰 비용 산식 (출처: beri.net 2026-10-16 분석)
가정: Claude Sonnet 5.5 입력 $2/1M, 영문 약 4자=1토큰, 전체 페이지 추출 텍스트 약 5,000토큰
워크로드: 질문 1,000개 × 질문당 검색 3회 × 결과 10개
- 발췌(스니펫·하이라이트)만: 검색당 약 3,750토큰 → 1,000질문에 약 1,100만 토큰 → 입력 비용 약 $22
- 전체 본문: 검색당 약 50,000토큰 → 약 1억 5,000만 토큰 → 약 $300
- 같은 워크로드의 검색 요금: Brave $15 / Tavily $24 / Exa $51 (Exa $51 = 검색 $21 + 결과별 하이라이트·콘텐츠 $30. 순수 검색 요금만 보면 $21)
→ 발췌면 검색 요금과 토큰 비용이 엇비슷, 본문을 넣으면 토큰 쪽이 Brave 대비 약 20배·Exa 대비 약 6배
- 추가 변수: 에이전트 루프는 매 턴 이전 툴 결과를 재전송 → 실제 토큰은 더 많음. 프롬프트 캐싱 시 Sonnet 5.5 재읽기 $0.10/1M. 더 싼 모델로 바꿔도 15만 토큰 컨텍스트는 Haiku 5.5에서 1,000질문당 약 $75로 어떤 검색 요금보다 큼.

## 바꾸는 것
에이전트를 운영하는 팀의 검색 비용 라인이 바뀐다 — 단, 바뀌는 지점이 공급자 가격표가 아니라 **컨텍스트에 무엇을 넣을지의 설계**다. 독자가 내일 회의에서 쓸 문장: "검색 API 공급자를 바꾸기 전에, 우리 에이전트가 한 과제당 검색을 몇 번 하고 결과 본문을 통째로 컨텍스트에 넣고 있는지부터 재자. 청구서는 거기서 결정된다." 더해서 조달 판단 하나 — 쿼리 문자열과 `ori_question`(사용자의 원 질문 원문)이 중국 서버로 간다.

## 설명할 메커니즘
**에이전트가 "웹을 검색한다"고 할 때 실제로 청구되는 두 개의 요금.** (1) 검색 API 요금은 요청당 고정이고 결과 개수와 무관하다. (2) 그 응답을 모델이 읽는 입력 토큰 요금은 응답 길이에 비례하고, 에이전트 루프에서는 턴마다 재청구된다. DeepSeek 응답이 snippet(100~200자) / summary(600~800자) / content(전체)로 3단 분리돼 있고 `need_content` 기본값이 false인 것은 바로 이 두 번째 요금을 겨냥한 설계다. 독자가 몰랐을 지점: 검색 API를 고를 때 비교하는 숫자(1,000건당 달러)가 정작 청구서의 지배적 항목이 아니라는 것.
