# 팩트 카드 — 2026-10-07 데일리

## 선정 토픽
OpenAI, 텍스트 워터마크 textGrain 공개. EU에서는 ChatGPT·Codex에 자동 적용, API는 전 세계 opt-in(기본 꺼짐).

## 선정 사유
- 복수 출처 교차 확인 가능(TechCrunch, 9to5Mac, ActuIA, 기술 보고서 요약 보도).
- 평론 각도가 선명: '표시'가 무엇을 표시하는가 — AI가 썼다는 사실이 아니라 어느 창구를 통과했는가.
- 엔지니어 독자 접점: API 기본값이 꺼짐이라는 사실, 탐지기 접근권 통제, 복붙은 살아남고 패러프레이즈는 죽는다는 성질.
- 중복 없음: topics-written.md에 워터마크/Article 50 관련 항목 없음.

## 날짜·주체
- 2026-10-05 OpenAI 발표 + 약 20쪽 기술 보고서 공개.
- EU AI Act(규정 2024/1689) 제50조 2항: 2026-08-02 발효. 기계 판독 가능한 형식으로 표시 + 인공 생성물로 탐지 가능해야 함.
- 제111조 4항: 8월 2일 이전에 이미 시장에 있던 시스템(ChatGPT 포함)은 2026-12-02까지 유예.
- 2026-06-10 EU 집행위 AI 생성 콘텐츠 실행규약(Code of Practice) 공개 / 2026-07-20 제50조 가이드라인.

## 기술
- 이름: textGrain.
- 샘플링의 난수를 '비밀 키 + 앞선 토큰들'에서 유도한 유사난수로 대체.
- 어휘를 블록으로 분할, 최적수송(optimal transport)으로 블록 선택. 비용은 Gumbel 확률변수에서, KL 정규화로 독립성 이탈에 페널티. 선택된 블록 안에서는 토큰의 원래 상대 확률을 보존.
- 숨은 문자나 보이지 않는 공백을 넣지 않는다 — 신호는 단어 선택 자체가 운반.
- 복사·붙여넣기로 유지됨. 탐지에는 생성 모델·생성 예산·사용된 coupling 불필요(비밀 키와 관측된 텍스트만).
- 모델 성능에 "유의미한 변화 없음"(OpenAI).

## 수치 (목표 오탐률 1% 기준)
- 400토큰(심리학 분야 지문) 약 95% 탐지 / 200토큰 약 80%.
- 수학 콘텐츠는 "상당히 낮음" — 400토큰에서 약 60%.
- 단어 10% 동의어 치환: 약 92% → 66%.
- 단어 25% 치환: 17%.
- 영어 프롬프트 500개를 EU 23개 언어로 번역: 루마니아어 42.2% ~ 스페인어 69.0%.
- 200토큰 하한은 EU 실행규약의 "매우 짧은 텍스트" 예외와 정렬.

## 배포
- ChatGPT·Codex: EU 한정, 모든 요금제, 수 주에 걸쳐 순차 적용.
- API: 전 세계 즉시 opt-in 가능하나 **기본 꺼짐**. 조직/프로젝트 설정의 Data controls에서 켬. Azure 연동 예정. 구형 모델 확대 진행 중.
- 탐지기: 승인된 연구자·전문기관에만(코넬, ETH 취리히, KInIT). EU 실행규약은 향후 규제기관·법집행·언론·팩트체커·독립 연구자·교육기관·시민사회로 확대 요구. **인사(HR) 부서 등 내부 사용자는 접근 제한.**

## OpenAI가 명시한 한계
- 워터마크가 없다고 사람이 썼다는 증거가 되지 않는다.
- 사용자를 식별하지 않는다.
- 인간의 기여도를 측정하지 않는다. 소유권이나 책임을 성립시키지 않는다.
- 오탐·미탐 존재. 짧은 글, 수학 등 도메인 특이 콘텐츠에서 특히.

## 비교 — 앤트로픽
- 2026-08-02 이후 출시된 모든 Claude 모델이 SynthID-Text 기반 워터마크를 모든 생성 텍스트에 삽입. 기본 켜짐, 사용자 opt-out 없음, **전 세계**.
- 회사 설명: 지역별로 신뢰성 있게 범위를 한정할 방법이 아직 없다. 구형 모델은 2026-12-02까지.
- SynthID-Text: 구글 딥마인드 고안, 2024년 10월 Nature 게재.
- 구글·vLLM은 탐지 도구를 오픈소스로 공개. vLLM은 Mistral·레드햇 엔지니어를 통해 Gumbel-max 워터마킹 통합.

## 평론 각도
1. 제50조 2항이 요구하는 것은 '기계 판독 가능한 표시'이지 'AI가 썼는지 알아내는 탐지'가 아니다. 용어부터 정의하고 들어간다.
2. 숨은 문자를 넣지 않고 단어 선택에 신호를 싣는다는 설계가 복붙 생존과 패러프레이즈 취약을 **동시에** 낳는다 — 같은 성질의 양면.
3. 비대칭: 있으면 OpenAI를 통과했다는 뜻이지만, 없으면 아무 뜻도 아니다(회사가 직접 그렇게 적었다). 고발 도구로 못 쓴다.
4. 탐지기를 중앙이 쥐고 HR에는 닫아 둔 것이 그 비대칭과 일관된다.
5. EU 한정 + API 기본 꺼짐 → 표시의 적용 범위를 정하는 것은 기술이 아니라 관할권과 기본값. 단, 앤트로픽의 전역 적용이 더 엄격한 태도라고 단정할 수 없다 — 회사 설명은 '지역 한정이 안 돼서'였다.
6. 엔지니어 실무: 탐지 시점이 아니라 생성 시점에 기록을 남기는 문제. 요청 ID·모델·타임스탬프·게이트웨이 로그.
