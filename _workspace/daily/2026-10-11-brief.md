# 팩트 카드 — 2026-10-11 (KST)

### 라이언 달 본인의 설명 (Hacker News, 사용자 `rough-sea`, 2026-10-09T16:51Z, 스레드 id 50019911 / 1,330 포인트 · 686 코멘트) — 축자 인용
> "It's a joint decision and I agree with it. I'm most invested in its success and have put the most work into it - and I no longer think it's where I can do the most important work. There are some good ideas in Deno and it's well engineered - but it ultimately is not solving big problems. **It has been sucked into the gravity well of node compatibility, which forces it to behave exactly as Node does. Why reimplement Node? It works. Marginal performance or UX or security benefits are not enough.** I'm interested in building powerful new abstractions. celld has been working remarkably well, depending only on object storage for coordination and persistence. It is not just a slightly different API to interact with the file system or network - it's an entirely new model for server development. We'll ship monthly releases for a year, and Deno stays MIT-licensed. If people want to carry it forward, I'd like that."

### celld
- Deno 팀이 **2026년 8월** 공개(2차 출처는 8/5). Rust 단일 바이너리. Apache-2.0.
- 클라우드플레어 Workers 프로그래밍 모델, 특히 **Durable Objects**의 자체 호스팅 구현.
- 구조: Durable Object마다 자체 SQLite DB, S3 호환 버킷으로 복제. 노드 간 조정은 버킷의 compare-and-swap. **컨트롤 플레인 없음, 합의 프로토콜 없음, 멤버십 서비스 없음.**
- 한계(논평자 지적): 셀 간 트랜잭션 없음, 엔티티 횡단 단일 질의 없음, 프로젝트 자체가 초기 단계.

### 배경 연표
- 2009: 라이언 달, Node.js 공개(JSConf EU 베를린).
- 2018: JSConf EU 강연 「10 Things I Regret About Node.js」에서 Deno 발표. 후회 목록에 **보안(패키지가 파일시스템·네트워크에 전면 접근), node_modules, package.json, GYP 빌드 시스템, 확장자 없는 require** 등. ⚠ 실제 강연에서 항목 수가 10개가 아니었다는 지적이 있으므로 **"10가지"를 단정하지 말 것** — 강연 제목으로만 인용.
- 2020-05-13: Deno 1.0.
- **2024-10: Deno 2.0** — package.json·node_modules·npm 워크스페이스 지원, `npm:` 지정자로 npm 모듈 사용, Next.js·Astro 등 프레임워크 지원. 즉 **노드 호환을 전면에 내세운 버전**. ⚠ 발표일은 출처에 따라 10/9(InfoWorld)·10/10(Socket)로 하루 차이 → 본문에서는 "2024년 10월"로만.
- 2019-07-11: 클라우드플레어가 선 마이크로시스템즈의 옛 구호 "The Network is the Computer" 상표를 USPTO에 등록(1984년 존 게이지 명명, 2010년 선 인수 뒤 미갱신). ※ 참고용 — 본문 사용은 선택.

### 평론 각도
1. **주 논지:** Deno를 끌어내린 것은 Node가 아니라 **Node 호환**이다. 2018년 후회 목록의 항목들은 Deno가 전부 고쳤는데, 사용자를 모으려고 택한 호환성이 "Node와 똑같이 행동하라"는 제약으로 돌아왔다. 달 본인이 "왜 Node를 다시 구현하나, 그건 잘 돌아간다"고 말한다.
2. **경쟁의 단위 이동:** 런타임(누가 API를 구현하는가) → 모델(어떤 추상 위에서 서버를 쓰는가). Deno의 마지막 의미 있는 엔지니어링이 **남의 프로그래밍 모델의 구현체**(celld)였다는 점.
3. **탈출구의 소유권:** 바르다의 "오픈소스 탈출구는 좋은 사업"은 진심이고 상업적으로도 입증됐다. 그런데 그 탈출구를 독립적으로 밀고 가던 팀이 이제 안으로 들어왔다. 코드가 닫히는 것이 아니라 **독립 구현을 유지할 주체가 비는 것**.

### 사정거리 (단정 금지 목록)
- "디노가 죽었다"는 2차 매체의 요약 — 공식 개발 종료 ≠ 코드 소멸. MIT 유지, 1년간 월간 릴리스, 달 본인이 계승을 환영.
- 클라우드플레어가 Deno를 "죽였다"는 구도 금지 — 달이 "공동의 결정이고 나도 동의한다"고 적음.
- "클라우드플레어가 celld만 보고 샀다"고 단정 금지 — 두 발표문이 모두 celld를 가리키지만 거래 동기는 공개되지 않음.
- 주가 5.6% 상승(360.93달러)은 단일 2차 출처 → 사용하지 않음.
- 누적 투자금 2,600만 달러도 2차 출처 → 쓰더라도 단정 회피.
- 오라클 JavaScript 상표 취소 심판의 현재 상태는 확인 불가 → **언급하지 않음.**
