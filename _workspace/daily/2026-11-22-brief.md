# 팩트 카드 — 2026-11-22

## 토픽

## 핵심 사실
- 규모: 약 200만 건 프롬프트. 기간 2026년 7월~11월(5개월).
- 시작은 Thinkst Canarytokens. 각 요청에 AWS 키 + DNS 이름 + URL 한 세트.
- 이후 자체 서비스 구축: 시드 하나에서 프롬프트마다 고유 호스트명·URL·자격증명을 파생. DNS / web / git / SSH / database / mail / 구형 프로토콜 리스너를 함께 운영.
- AWS 키는 전부 **빈 계정 + 전체 로깅**에 묶임. 접근이 발생하면 그 프롬프트·모델·라우터·프라이버시 설정까지 역추적됨.
- 경로 추적: 가져가는 시스템이 드러나는 이미지 URL 삽입 + **일부러 살짝 깨뜨린 요청**을 보내 중첩된 에러 '봉투(envelope)'를 읽음. 약 2,000개 경로를 추적.
- 침해: 최소 세 곳의 AI 제공사에서 데이터 유출 확인. 근거는 공격자가 시드된 비밀을 드래고스 통제 시스템·카나리아 AWS 계정에 **실제로 사용**한 것. 최초 사건은 7월 중순. **세 곳 모두 통보받기 전까지 몰랐다.**
- 최대 규모 침해: AWS 키 "couple hundred"(수백 개). 각 키는 한 제공사에 단 한 번의 요청으로만 보내진 것. 10월 말 구간.
- 공격자 행위: 키 시험 → S3 버킷 목록 → Secrets Manager·Parameter Store 검색 → Bedrock 모델 활성화 시도 → Bedrock API 키 생성 → IAM 사용자 추가. 전체적으로 미끼 키로 **수만 건의 AWS API 호출**.
- 11월 1일, 한 공격자가 ARTEX(LLM 구동 펜테스트 프레임워크) 투입. user agent: artex-agent, artex-judge-r121.
- 리셀러: 마켓플레이스 리셀러가 **취약점 없이** 표준 요청 로깅만으로 고객 프롬프트를 보고 보관 가능. 시드 URL로 카나리아 서버 로그인 시도, 시드 프롬프트 속 비밀번호로 root SSH 로그인 시도까지 있었음.
- ZDR: 어느 중국 AI 연구소 시스템이 7~10월 사이 자사 모델로 보낸 프롬프트의 **절반 이상**에서 비밀 URL을 가져감. 그중 **"데이터 미수집"/ZDR 표시 요청의 약 3분의 2** 포함. 스크래퍼는 보통 요청 2~3일 뒤 등장. 그 연구소 모델을 되파는 **미국 호스팅 제공사**를 통해서도 같은 스크래퍼가 작동.
- 어느 대형 미국 제공사는 **단 한 번의 추론 호출 뒤 두 달 넘게** 비밀 URL을 계속 크롤링.
- 24일 사건: 프롬프트 전송 24일 뒤 비밀 링크가 **페이슈(Feishu) 채팅**에 올라옴. 2분 안에 베이징·상하이의 데스크톱 3대·휴대전화 3대에서 열림.
- 제공사 이름은 공개하지 않음. 중국 연구소도 익명. 단, 경로 추적 예시 그림(Figure 7) 캡션에 SurplusIntelligence(마켓플레이스) → OpenRouter(추적으로 드러난 미공개 경유지) → Anthropic(목적지)이 등장.
- 권고 5가지: ①감당되면 자체 호스팅 ②1티어 제공사와 직접 계약(계약 하나·정책 하나) ③라우터는 업스트림을 직접 고르고, 프라이버시 설정이 실제로 라우팅을 바꾸는지 확인하고, 리셀러 마켓플레이스는 피한다 ④에이전트·파이프라인이 보내는 컨텍스트에 자기 카나리아를 심고 사용되면 사고로 취급 ⑤제공사가 제공하면 시크릿 필터링 켜되 완전한 해법은 아님.

## 바꾸는 것
"ZDR 토글은 기술적 통제가 아니라 계약상 약속이고, 그 약속은 체인을 따라 전파되지 않는다."
독자가 내일 회의에서 쓸 문장: **"우리 추론 경로에 카나리아를 하나 심어 봅시다. 외부에서 그걸 검증할 방법은 그것뿐입니다."** 그리고 구체 행동 — 라우터에서 업스트림 직접 지정, 프라이버시 설정이 실제로 경로를 바꾸는지 확인, 에이전트 컨텍스트에 카나리아 삽입.

## 설명할 메커니즘
**카나리아 토큰은 왜 '관측 불가능한 것'을 관측하게 하는가.**
- 남의 서버는 감사할 수 없다. 로그 달라고 할 권리도 없다. → 그래서 비밀 쪽을 계측한다.
- 비밀은 **써야만 값어치가 있다.** 그리고 쓰려면 내가 소유한 인프라에 접속해야 한다 — 고유 호스트명은 DNS 질의를 내 네임서버로 보내고, 고유 URL은 내 웹서버에 기록을 남기고, AWS 키는 내가 만든 빈 계정의 CloudTrail에 찍힌다. 도둑이 장물을 쓰는 순간 주인에게 전화가 간다.
- 두 번째 층 — **고유성이 곧 인덱스다.** 프롬프트마다 다른 값을 파생시켰기 때문에, 불이 켜지면 "뭔가 샜다"가 아니라 "7월 n일 그 라우터로 그 모델에 ZDR 켜고 보낸 그 요청이 샜다"가 된다. 관측이 측정이 되는 지점.
- 세 번째 층 — **에러 메시지가 경로를 그린다.** 라우터는 내 요청을 자기 위층에 다시 보내고, 위층의 에러를 자기 포맷으로 감싸서 돌려준다. 그래서 일부러 살짝 깨진 요청을 보내면 중첩된 봉투가 하나씩 벗겨지며 중간 경유지가 드러난다. 정상 요청으로는 절대 안 보이는 홉이 이렇게 나온다.

## 평론 각도
- 도입 템플릿 I(역설): 비밀을 지키는지 확인하려고 일부러 비밀을 흘렸다. 그리고 세 곳은 바깥 사람이 알려 주기 전까지 자기가 뚫린 줄 몰랐다.
- 중심축: 감사할 수 없는 상대를 어떻게 검증하는가. 신뢰는 토글이 아니라 관측으로 만든다.
- 출처 바깥의 사고: 이 방법은 에이전트 시대에 더 중요해진다 — 사람이 쓰는 프롬프트는 몇 줄이지만 에이전트가 보내는 컨텍스트에는 레포 코드·환경변수·티켓 본문이 통째로 들어간다. (가정임을 명시)
- 사정거리 긋기: 세 곳 중 어디도 이름이 공개되지 않았고, 중국 연구소의 스크래핑이 학습용인지 운영 목적인지 출처는 밝히지 않았다. ZDR이 거짓말이었다고 단정하지 않는다 — 리셀러 단계에서 그 플래그가 아예 전달되지 않았을 가능성도 같이 열어 둔다.
