- **시점 붕괴 여부: 없음.** 26줄의 "10월 27일에 ... 루트 자체가 빠집니다"는 현재형-미래 의미로, 완료형으로 쓰이지 않았다. 다른 문단에도 사후 시점 표현("훗날", "결국 드러났듯")은 없다.
- **"10월 27일" 요일 검증:** 2026-10-17이 토요일 → 10-27은 화요일. 구글 공지의 "Tuesday, October 27, 2026 PDT"와 일치. ✓
- **주의(경미):** 본문의 모든 시각은 **UTC 기준**이다. 12줄 "10월 17일 저녁"은 18:05 UTC를 가리키는데 KST로는 **10월 18일 새벽 3시 5분**이다. 한국 독자 기준으로는 날짜가 하루 어긋난다. (레포 규칙상 `현지시각` 표기는 금지이므로, "10월 17일 저녁" → "10월 17일(UTC)" 또는 "저녁"만 삭제 권고. 모든 보도가 10/17로 쓰고 있으므로 날짜 자체를 10/18로 바꿀 필요는 없다.)
- **용어 시점성:** CRLSet, OneCRL, Certificate Transparency, P-384, certifi — 모두 2026-10 기준 존재. ✓

## C. 수정 권고 (우선순위 순)

**1. [정정 — 발행 전 반영 권고] 24줄: CT 서술의 "여덟 개" → "여섯 개"**
- 현재: "이 여덟 개에서 내려온 인증서가 로그에 올라온 적이 한 번도 없었다"
- 문제: 구글 공식 발표는 **TLS용 중간 CA 여섯 개**에 대한 진술이다. 코드 서명 인증서는 CT 로그 대상이 아니므로 "여덟 개가 CT에 없었다"는 말은 출처를 넘어설 뿐 아니라 개념적으로도 어긋난다. (커뮤니티 사이트 we-have-a-problem.com은 "이 중간 CA들에 대한 CT 엔트리가 없다"고 포괄적으로 쓰지만, 원전인 구글 쪽이 더 정확하다.)
- 권고: "이 여덟 개에서" → **"웹 인증서용 여섯 개에서"** 또는 "이 CA들에서 내려온 웹 인증서가".

**2. [정밀도] 26줄: 10월 27일 루트 제거 서술**
- 현재: "10월 27일에 크롬 루트 스토어에서 이 중간 CA들을 서명한 루트 자체가 빠집니다."
- 문제 둘. (a) 루트는 이미 크롬 루트 스토어(소스·프리릴리스)에서 빠졌고, **10/27(PDT)은 크롬 루트 스토어 v43이 모든 기기 정식 채널에 도달하는 날**이다. (b) 이 중간 CA들을 서명한 루트는 **둘**인데(eMudhra의 emSign ECC Root CA - G3, Sectigo의 AAA Certificate Services 교차서명) 제거되는 것은 eMudhra 쪽 하나다. 현재 문장은 "서명한 루트"를 하나로 단정한다.
- 권고 예: "10월 27일부터는 크롬 전 사용자에게 eMudhra의 ECC 루트 제거가 적용됩니다." (교차서명 루트까지 설명을 벌릴 필요는 없으므로, 루트를 특정하는 쪽이 간단하다.)

**3. [경미] 12줄: "중간 CA 인증서 8장"**
- 키 기준으로는 8개이고, 같은 키가 eMudhra 발급본과 Sectigo 교차서명본 두 장씩에 들어가 **인증서는 총 16장**(모질라 차단 목록도 16장)이다.
- 권고: "중간 CA 인증서 8장" → "중간 CA 8개". 22줄의 "이번 여덟 장"도 같이 "여덟 개"로. (사소하지만 "8장"이라고 쓰면 16장을 센 모질라 목록과 숫자가 충돌한다.)

**4. [경미] 12줄: 제보 대상**
- 제보자는 구글 한 곳이 아니라 **구글·모질라·애플·마이크로소프트·eMudhra에 같은 날 동시에** 알렸다. 현재 문장("크롬 루트 프로그램에 제보를 넣었습니다")은 뒤이은 "모질라도 같은 날, 애플은 19일"과 붙어 읽히면 다른 벤더가 뒤늦게 통보받은 것처럼 읽힐 수 있다. (excerpt는 "브라우저 제조사에 찾아왔습니다"로 이미 정확하다.)
- 권고: "브라우저 제조사들에 제보를 넣었습니다. 크롬 루트 프로그램이 받은 시각은 ..." 식으로 한 겹만 풀거나, 현행 유지하되 뒷 문장에서 "애플은 19일, 마이크로소프트는 20일에 **뒤이어** 막았습니다" 같은 인과 암시를 넣지 않는다(현재는 넣지 않았으므로 유지해도 치명적이지 않음).

**5. [경미] 22줄: 위조 가능성의 사정거리**
- "중간 CA의 비밀키를 손에 넣으면 ... 원하는 도메인 이름으로 ... 찍어 낼 수 있다" 바로 뒤에 "여덟 장 중 여섯 장이 웹 인증서용, 두 장이 코드 서명용"이 와서, 여덟 개 모두 도메인 위조가 가능한 것처럼 읽힐 수 있다. 실제로 코드 서명 중간 CA는 EKU로 제한돼 TLS 경로를 만들 수 없고, 구글도 "코드 서명 중간 CA는 크롬 TLS 검증기가 경로를 세우지 않으므로 차단할 필요가 없었다"고 밝혔다.
- 권고: "여섯 장이 웹 인증서 발급용(도메인 위조가 가능한 쪽), 두 장이 코드 서명용" 정도의 한 마디.

**6. [경미] 24·26·28줄: "17개월"**
- 2025-04-30 → 2026-10-17은 **17개월 17일**. 틀린 수는 아니지만 세 번 반복되며 단정적으로 읽힌다.
- 권고: 첫 등장만 "약 17개월"로.

**7. [경미] 12줄: "10월 17일 저녁"**
- 18:05 UTC는 KST로 10월 18일 새벽이다. 날짜 자체는 모든 출처가 10/17로 쓰므로 유지하되, "저녁"은 한국 독자에게 오해를 준다.
- 권고: "10월 17일" 또는 "10월 17일(UTC)".

**8. [선택] 26줄: Go는 이미 긴급 업데이트가 나왔다**
- Go는 1.27.3·1.26.10에서 해당 체인을 **거부하도록 패치**됐다. 본문은 Go 번들을 "아무 일도 일어나지 않는" 쪽에 함께 묶었는데, 바로 다음 문장이 "패키지를 올리고 다시 빌드해야 바뀝니다"라 결론은 어긋나지 않는다. 다만 "런타임 쪽은 긴급 업데이트가 나온 곳도 있지만, 올려야 적용됩니다" 한 마디를 넣으면 더 정확하다. (반영하지 않아도 오류 아님.)

**9. [선택] 34줄: 커버 사진의 피사체**
- eMudhra가 쓴 HSM은 **Utimaco**(일부 계열은 Entrust)이고 커버 사진은 **nCipher nShield F3**다. 캡션이 "eMudhra의 HSM"이라고 주장하지 않으므로 사실 오류는 아니지만, 이번 사건의 장비와 다른 제조사라는 점은 알고 두는 편이 좋다. 크레딧 줄은 `_workspace/image-credits-2026.md` 150행과 일치하며 파일도 실재한다. ✓
