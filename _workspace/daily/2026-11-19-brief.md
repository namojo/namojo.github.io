# 팩트 카드 — 2026-11-19 (KST)

## 토픽
마이크로소프트 Ignite 2026에서, 직원 노트북에서 돌아가는 **로컬 코딩 에이전트(Claude Code, GitHub Copilot CLI)**에
회사 디렉터리가 자동으로 신원(Entra Agent ID)을 붙이기 시작했다.

## 날짜·주체
- **Microsoft Ignite 2026**: 2026-11-17 ~ 11-20, 모스콘 센터(샌프란시스코) + 온라인. 발표는 11/17부터.
- 주체: 마이크로소프트 (Entra / Defender / Intune / Agent 365)
- 사티아 나델라: Agent 365에 등록된 에이전트가 5,000만 개를 넘었다고 언급 (Agent 365는 2026-05 출시)

## 핵심 사실 (Book of News + Agent 365 공식 블로그)
1. **Entra Agent ID — "Agent ID for discovered local agents"** : **프리뷰**.
   발견된 로컬 에이전트에 Agent ID를 부여. **GitHub Copilot CLI와 Claude Code가 시작점.**
   목적 문구(원문): "to separate agent activity from human activity"
2. **Entra Global Secure Access — "Local agents"** : 프리뷰.
   로컬 에이전트와 그 **목적지(destinations), MCP 서버, 리소스**에 대한 네트워크 가시성·제어
3. **GSA — "MCP Firewall"** : 프리뷰. MCP 서버의 tools / resources / prompts / protocols / transports 접근 제어
4. **GSA — "Unsanctioned agents"** : 프리뷰. Intune·Defender·GSA 정책을 Agent 365로 묶어 조율
5. **GSA — "Agentic traffic acquisition"** : **GA**
6. **Defender 런타임 보호(Windows)** : 에이전트 네이티브 보호 **GA** —
   Claude Code, GitHub Copilot CLI, GitHub Copilot 앱, Claude Desktop(Code), VS Code 확장(Copilot·Claude Code).
   네트워크 기반 보호 GA — Open Claw, Ollama Desktop, ChatGPT Classic/Desktop.
   **Defender for Endpoint P2 필요.** Audit 또는 Block 모드. 로컬 에이전트 호출에서 악성 은닉 지시를 검사.
7. **Intune 로컬 AI 에이전트 거버넌스 컨트롤** : 프리뷰.
   Agent 365로 관리 단말의 에이전트를 발견 → 미승인 에이전트가 있는 단말을 **비준수(noncompliant)** 로 표시 →
   Entra 조건부 액세스로 회사 데이터 접근 차단
8. Agent 365 블로그: Defender + GSA가 **60개 이상의 로컬 AI 에이전트**와 **그들이 설정해 둔 MCP 서버**를 발견.
   Defender는 관리되는 Windows·macOS 단말 지원, **에이전트를 단말·사용자에 묶는다.**
   - Defender의 로컬 에이전트 발견: GA / GSA 네트워크 발견: 프리뷰 / Agent registry의 섀도 AI 발견: 프리뷰
9. 연결형(클라우드) 에이전트도 Entra Agent ID 자동 부여 — Salesforce Agentforce, Amazon AgentCore,
   Google Vertex AI, Databricks, Snowflake, Anthropic Claude Managed Agents, 오픈AI, Oracle, SAP,
   ServiceNow, UiPath. 롤아웃 중, 12월 완료 예정.

## 설명할 메커니즘 — "에이전트에 신원을 준다"가 실제로 무엇인가
출처: Microsoft Learn, "Agent identities, service principals, and applications" (ms.date 2026-11-03, updated 2026-11-17)

- 에이전트 신원은 **서비스 주체(service principal)** 인프라 위에 "agent" 하위 유형으로 올라간 **별개의 객체 유형**이다.
- 기존 서비스 주체는 "정적·결정적 워크로드"를 위해 설계됐고 **자기 자격증명으로 직접** 토큰을 받는다.
- 에이전트 신원은 다르다. **블루프린트(blueprint)** 라는 상위 주체가 있고, 다중 인스턴스 모드에서는
  **위임(impersonation) 모델**을 쓴다 — 원문: "the agent identity blueprint acquires tokens on behalf of
  each child identity, so the agent identity appears as the client in the resulting token and in audit logs,
  even though the blueprint performed the initial token exchange."
- 즉 **쪼개진다**: "the blueprint holds the authentication credentials while the agent identity holds the
  permissions and the audit identity." → 인증(자격증명)은 블루프린트, 인가(권한)와 감사 신원은 에이전트.
- 블루프린트 하나가 테넌트 안팎으로 **다수의 Agent ID를 찍어낼 수 있다**(1:N).
- ⚠ 문서가 직접 적은 경계: "A compromise of the blueprint's credentials affects all agent identities under it,
  which is why blueprint count is a security boundary decision."
- 에이전트 신원은 **지정된 스폰서(assigned sponsor)를 요구**한다. (원문: "require an assigned sponsor")
- 감사 로그: 에이전트 활동은 서비스 주체 이벤트로 남고 `agentType` 속성으로 구분. 로그인 로그는
  Agent ID user / Agent Identity / Agent Identity Blueprint / Not Agentic 으로 분리.

### 독자가 오늘 처음 알게 되는 원리 하나
**신원 수명주기가 거꾸로 돈다.** 보통은 관리자가 먼저 신원을 만들고 워크로드가 그걸 가져다 쓴다(등록 후 사용).
로컬 CLI 에이전트는 이미 수천 대 노트북에서 돌고 있고 디렉터리에 등록된 적이 없다. 그래서 순서가 뒤집혔다 —
**엔드포인트(Defender: 프로세스를 보고 단말·사용자에 묶음)와 네트워크(GSA: 어디로 나가는지, 어떤 MCP 서버를
붙들고 있는지)에서 먼저 "발견"한 다음, 이미 돌고 있는 것에 신원을 사후 발급한다.**
그리고 그 신원은 자격증명(블루프린트)과 감사 신원(Agent ID)이 분리된 구조라서, 자격증명 하나를 공유하면서도
로그에는 에이전트별로 따로 찍힌다.

## 바꾸는 것 (독자가 내일 회의에서 쓸 문장)
- **지금 우리 감사 로그에서, Claude Code가 호출한 내부 API는 전부 그 개발자의 계정으로 찍혀 있다.**
  에이전트가 한 일과 사람이 한 일을 사후에 가를 방법이 없다. (MS가 적은 목적 문구가 정확히 이것: separate
  agent activity from human activity)
- 확인할 항목 넷:
  ①관리 단말에서 어떤 로컬 에이전트가 돌고 있는지 목록이 있는가
  ②그 에이전트들의 **MCP 서버 설정이 무엇을 가리키는가** (발견 대상에 MCP 서버가 포함된 이유)
  ③에이전트가 쓰는 토큰이 사람 토큰인가 별도 주체인가
  ④사람이 퇴사하면 그 에이전트는 어떻게 되는가 (스폰서 개념)
- 조달·라이선스 축: Defender 런타임 보호는 **Defender for Endpoint P2**가 전제. Audit/Block 모드 선택.
- 사정거리: Agent ID for local agents는 **프리뷰**, 지원 에이전트 2종(Copilot CLI·Claude Code)부터.
  Intune 통제도 프리뷰. "오늘 켜면 되는 것"이 아니라 "지금 설계를 정해 둘 것".

- 스폰서가 퇴사·이동할 때 에이전트 신원의 수명주기
