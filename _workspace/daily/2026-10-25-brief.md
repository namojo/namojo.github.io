## 핵심 사실

### 1) 깃허브 패키지 방화벽 (1차 출처: GitHub Changelog, 2026-10-20)
- https://github.blog/changelog/2026-10-20-github-package-firewall-in-public-preview/
- 퍼블릭 프리뷰 시작: 2026-10-20
- 위치: 엔드포인트/사내 레지스트리와 업스트림 패키지 저장소 **사이**에 선다.
  메타데이터 요청과 패키지 다운로드를 **둘 다** 검사한다 → 설치 시점 정책 게이트
- 지원 생태계: **현재 npm만**
- 대상: GitHub Enterprise Cloud 고객(데이터 레지던시 포함)
- 설정 가능 정책: 쿨다운 기간(범위는 체인지로그에 미명시), GitHub Advisory
  Database의 멀웨어·취약점 권고 검사, 공급망 검사(예: 어테스테이션 다운그레이드)
- 과금: 프리뷰 무료. GA 시 Actions와 유사한 사용량 과금 예정. GA 날짜 미발표
- 오탐 차단 시 예외 요청 워크플로 제공(GHAS 유사)
- 체인지로그 직접 언급: **에이전트와 CI 러너는 사람이 개입하지 않은 채
  의존성을 설치하기 때문에 특히 취약**하다. 코딩 에이전트·CI/CD 호스트 같은
  엔드포인트는 업스트림에 직접 가지 말고 방화벽을 거치게 하라.
- 한계(체인지로그·2차 보도): 트래픽을 방화벽으로 **라우팅해야만** 효과가 있고
  우회 요청은 보호 밖. 지연형 멀웨어·탈취된 퍼블리싱 파이프라인으로 서명된
  악성 릴리스까지 잡는다고 보장하지 않음. 인프라 확장 중

  출처: safedep.io 분석

## 바꾸는 것
독자(플랫폼·SRE·보안 담당)가 내일 회의에서 쓸 수 있는 것:
1. "우리 CI 러너와 코딩 에이전트가 npm에 **직접** 나가고 있나?" — 방화벽이든
   사내 프록시든, 라우팅되지 않은 경로가 있으면 정책은 종잇장이다.
2. 쿨다운 일수를 **정책으로** 정한다. Dependabot은 이미 3일이 기본값이고,
   보안 업데이트는 예외라는 점까지 같이 안다.
3. CI에서 `ignore-scripts=true` — @antv 웨이브의 실행 경로가 `preinstall`이었다.
4. 조달·라이선스가 아니라 **설치 시점**에 게이트가 생겼다는 것이 변화다.
   SCA 스캔은 커밋된 락파일을 보지만, 악성 버전은 설치되는 순간 이미 실행된다.

## 설명할 메커니즘 (독자가 오늘 처음 알게 될 원리 하나)
**왜 '기다리는 것'이 방어가 되는가.**
- 탐지는 결국 따라잡는다. 다만 몇 시간~며칠 걸린다.
- 공격의 수익 구간은 그 사이다. 22분 만에 637개 버전을 뿌리는 이유가 그것이다.
- 쿨다운은 탐지를 빠르게 만들지 않는다. **내 설치 시점을 탐지 뒤로 미룰 뿐이다.**
- 그래서 설치 시점 게이트가 필요하다 — 락파일은 '무엇을 쓸지'를 고정하지만,
  새 버전을 당겨오는 순간(범위 해석, 신규 의존성, 간접 의존성)은 여전히 열려 있고
  `preinstall`/`postinstall`은 사람이 코드를 보기 전에 실행된다.

## 출처 바깥의 사고 (가정임을 명시할 것)
쿨다운은 "탐지가 따라잡을 시간을 산다"는 설계라서, **탐지가 따라잡지 못하는
공격에는 약하다.** 근거 둘: npm이 게시 시점 스캐닝으로 5~15분을 보류하자 그
뒤에 재게시된 사례가 나왔고, Shai-Hulud 페이로드가 111일 뒤에 다시 떠올랐다.
→ 쿨다운이 보편화될수록 공격자가 지연 폭발 쪽으로 옮겨갈 유인이 커진다는
가정(예측 아님).
또 하나: 쿨다운은 구조적으로 "남이 먼저 설치해서 먼저 터지기를 기다리는" 전략이다.
모두가 걸면 첫 설치자는 누가 되는가 — 이건 질문으로 남긴다.

## 평론 각도
"설치 시점"이라는 층이 보안의 새 경계선이 됐다. 그 층이 왜 지금 생겼는지는
에이전트 때문이다 — 사람이 `npm install`을 치던 시절에는 적어도 누군가 그
순간에 앉아 있었다.
