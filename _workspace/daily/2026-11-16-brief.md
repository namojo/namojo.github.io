# 팩트 카드 — 2026-11-16 (KST)

## 토픽
Apache HTTP Server mod_http2 경쟁 상태 원격코드실행 (CVE-2026-119618), 2.4.71로 수정

## 핵심 사실 (1차 출처: httpd.apache.org 보안 권고 + apache/httpd 커밋)
- CVE-2026-119618, 등급 **critical**. 설명 원문: "Concurrent Execution using Shared Resource
  with Improper Synchronization vulnerability in Apache HTTP Server's mod_http2 in
  assign_headers() can lead to RCE." 권고 제목: "mod_http2: heap corruption and RCE in assign_headers"
- 영향: Apache HTTP Server **2.4.55 ~ 2.4.70** (HTTP/2 활성 시). HTTP/1.1 전용 서버는 미영향.
  GitHub 단독 배포 mod_h2 **2.0.8 ~ 2.0.42**도 영향.
- 수정: **2.4.71, 2026-11-11 릴리스**. 커밋 `824beab`(5ed3928 체리픽), 2026-11-11.
- **공개된 workaround 없음.** Apache 권고에 완화책 항목 자체가 없다. (Censys 확인)
- 2.4.71에는 mod_vhost_alias 1바이트 스택 오버라이트(CVE-2026-109163, low)도 함께 수정됨.
- **2.4.55 릴리스일 = 2023-01-18** → 취약 코드가 약 3년 10개월 존재.
- 보고 타임라인(Apache 권고 Acknowledgements/timeline 원문):
  - finder: **Anthropic's OSS Scanner**, 내부 식별자 ANT-2026-MAPKT6MZ — 보고 **2026-10-26**
  - finder: **Anthony Weems, Simon Scannell (Google Cloud Vulnerability Research)** — 보고 **2026-11-03**
  - → 독립 보고 **8일 간격**
- 악용: 2026-11-12 기준 공개 PoC 없음, 야생 악용 보고 없음, CISA KEV 미등재. NVD는 Received 상태라 CVSS 미부여.
  (Red Hat 쪽에서 "기본 설정 서버 대상 신뢰성 있는 익스플로잇이 공개 연구로 시연됐다"는 2차 전언이 있으나
   1차 확인 안 됨 → **본문에서 쓰지 않는다**.)
- 노출 규모: Censys — 영향 버전대를 보고하는 호스트 약 **150만**. 단 Censys 데이터에 HTTP/2 활성 여부
  필드가 없어 필터링되지 않은 수치이며, 실제 취약 대상은 이보다 적다. (버전은 Censys가 관측하는
  약 1.66억 Apache 자산 중 40% 정도에서만 식별됨)

## 커밋이 실제로 바꾼 것 (mechanism의 핵심)
`modules/http2/h2_request.c`의 `assign_headers()`, **단 한 줄**:
```c
- apr_table_setn(req->headers, "Content-Length", "0");
+ apr_table_setn(r->headers_in, "Content-Length", "0");
```
커밋 메시지: "mod_http2: assign_headers update table (#975) (#977)". 락·뮤텍스 추가 없음.
주변 주석: "If we have a content-type, but already seen eos, no more data will come.
Signal a zero content length explicitly."

## 설명할 메커니즘
**HTTP/2에서 버그의 종류가 '파싱 오류'에서 '소유권 위반'으로 옮겨갔다.**
- HTTP/1.1: 커넥션 하나에 요청 하나씩 직렬 처리. 그 요청을 다루는 주체가 하나뿐이라 공유가 없다.
- HTTP/2: 커넥션 하나에 스트림 여러 개가 동시에 흐른다(멀티플렉싱). mod_http2 공식 문서 인용:
  "HTTP/2 gives all requests that it receives to its own Worker threads for processing, collects
  the results and streams them out to the client." 이 H2Worker는 MPM 워커와 **별도 스레드 풀**이고,
  `H2MaxSessionStreams` 기본값이 **100** — 커넥션 하나에 요청 100개가 동시에 떠 있을 수 있다.
  문서도 "HTTP/2 keeps more state on the server to manage all the open request"라고 적어 둔다.
- 그래서 mod_http2는 프레임을 읽는 쪽(세션/주 커넥션)과 요청을 실행하는 쪽(워커)으로 갈라지고,
  데이터가 스레드 경계를 넘어가야 한다.
- APR 메모리 풀과 `apr_table_t`는 스레드 안전하지 않다. 테이블에 항목을 더하면 내부 배열이
  그 테이블이 속한 풀에서 다시 할당될 수 있다. 두 스레드가 같은 테이블을 동시에 건드리면 힙이 깨진다.
- `req`(h2_request)는 세션 쪽에서 만든 객체, `r->headers_in`은 워커가 돌리는 요청의 것.
  워커가 `req->headers`에 쓰는 것은 **남의 테이블에 쓰는 일**이었다. 고친 것은 "누구 것에 쓰는가" 한 줄.
- ⚠ Apache는 메커니즘 분석을 공개하지 않았다. 위 연결은 권고의 CWE-362 + 커밋 diff + 공식 문서의
  스레드 모델로부터 **내가 읽어낸 것**임을 본문에서 밝힌다. 단정하지 않는다.

## 바꾸는 것 (독자가 내일 할 일)
1. `Protocols` 지시자는 메인 설정만이 아니라 **가상호스트마다** 따로 적힐 수 있다. `h2`/`h2c`가
   들어간 줄을 전부 찾아야 노출 범위가 나온다. (Censys도 가상호스트별 확인을 권한다)
2. 2.4.71 또는 배포판 패치 패키지로 올린다. 배포판은 백포트하므로 버전 문자열이 2.4.71이 아니다 —
   `httpd -v`가 아니라 배포판 권고의 패키지 버전으로 판단한다.
3. **패키지를 올려도 실행 중인 프로세스는 옛 모듈을 메모리에 들고 있다.** 재시작해야 끝난다.
4. 소스에서 받아 쓴 단독 mod_h2(2.0.8~2.0.42)는 httpd 패키지와 별개다. 2026-11-12 기준 Apache 권고에
   수정 릴리스가 적혀 있지 않았다.
5. workaround가 없으므로, 당장 못 올리면 선택지는 HTTP/2를 끄는 것뿐이다.

## 출처 바깥의 사고 (가정임을 명시할 것)

→ 가정: 기계가 같은 코퍼스를 훑기 시작하면 "발견"은 더 이상 희소 사건이 아니고,
  수선 전 노출 구간(발견~패치 적용)이 실질적 위험 구간이 된다.
→ 근거 (a) 8일 간격 독립 보고 자체 (b) Anthropic 대시보드(2026-11-02 기준): 후보 37,966건,
  외부 검증 6,376건, 유효 6,009건, 메인테이너 보고 5,087건, 상류 패치 **629건**.
  대시보드 스스로 "patched = 수정이 릴리스됐다는 뜻이지 널리 설치됐다는 뜻이 아니다"라고 적어 둠.
  ※ VulnCheck는 같은 원장에서 fixed 217건으로 세어 수치가 엇갈린다 → **숫자를 단정해 쓰지 말 것.**
    본문에서는 비율의 자릿수(10% 안팎) 수준으로만 쓰고, 출처 간 불일치를 밝힌다.
