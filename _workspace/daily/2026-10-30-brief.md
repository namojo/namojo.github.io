# 팩트 카드 — 2026-10-30

## 토픽
AWS TorchNeuron — 파이토치 네이티브 백엔드가 Trainium을 정식 디바이스로 등록

## 날짜·주체
- 2026-10-20 (현지): AWS가 **TorchNeuron** 공개 베타 출시. PyTorch Conference North America에서 Apache 2.0 오픈소스 공개.
- 주체: AWS Annapurna/Neuron 팀 + PyTorch 커뮤니티(Meta)
- 리포지토리: github.com/aws-neuron/torch-neuronx
- 설치: `pip install torch-neuronx` (AWS Neuron pip repo)

## 핵심 사실 (PyTorch 공식 블로그 = 1차 출처)
- `.to('neuron')` 한 줄로 기존 파이토치 코드가 Trainium에서 실행. "the only change".
- **PrivateUse1** 디바이스 백엔드 + `torch.accelerator` API 위에 구축. PyTorch 커뮤니티가 만든 "official extension point for registering custom hardware".
- 지원: eager 실행, `torch.compile`, NKI(Neuron Kernel Interface) 커스텀 커널. Trainium2·Trainium3.
- 표준 API 동작: `torch.nn`, `torch.tensor`, `torch.autocast`, `torch.distributed`, `torch.profiler`.
- eager 모드 동작 방식: 연산을 즉시 실행. 각 연산이 **자기 NEFF(Neuron Executable File Format) 파일을 컴파일**하고 디바이스에 올리고 중간값을 HBM으로 옮긴다. 그래서 launch cost가 큼 → "adaptive eager mode"(실험적)로 완화 시도.
- torch.compile 경로: TorchDynamo → FX 그래프 → AOTAutograd → Neuron 백엔드 → **Torch-MLIR → StableHLO** → Neuron 컴파일러 → NEFF.
- Hugging Face: Transformers v5 / Diffusers / trl / kernels에 Trainium이 **upstream 지원**. `device_map="neuron"`, `device_map="auto"`로도 탐지.
- 인용: Jana van Greunen, Director of PyTorch Engineering at Meta — "developers should have a consistent experience across hardware platforms."

## ★ 사정거리 — AWS가 스스로 공개한 한계 (논지의 핵심)
- **블라인드 스윕**: Hugging Face 모델 10만 개를 상시 실행(다운로드 수 기준 실사용의 99.9% 커버). 기록 항목에 **"which operators executed on the device versus fell back to CPU"** 가 명시적으로 들어 있음.
- **PyTorch upstream 테스트**(2026-08 실행): 약 15만 4천 건 결과 중 약 6만 9천 건 skip. 그중 약 3만 건은 PyTorch 자체 eligibility(CUDA 전용/CPU 전용), **나머지 약 3만 9천 건이 의도적 Neuron skip**.
  - 그 3만 9천 중 **최대 그룹이 약 2만 2천 건 = "Operators without a native Neuron lowering"** (elementwise·reduction·foreach·advanced-indexing·advanced-linalg의 코너 케이스, fused LSTM/GRU 셀).
  - 1차 릴리스에서 **의도적 미지원**: sparse tensor/ops, NestedTensor, forward-mode autograd(JVP), **dynamic and symbolic shapes**, per-channel quantization, 임의 attention 마스크(no-mask·causal만 지원), bilinear/bicubic upsample 등.
- FP8·TorchAO는 private Beta (다음 릴리스에 GA 예정).
- 고객 수치(벤더/고객 주장, 독립 검증 아님): Deepgram CTO Adam Sypniewski — "Trainium processes about 60% more input audio seconds per dollar than our existing GPU baselines" (자사 벤치마크 범위 내).
- AWS는 CUDA 하드코딩 가정을 걷어내는 PR을 upstream PyTorch에 다수 제출(블로그 Appendix에 26건 링크).

## 바꾸는 것 (게이트 1)
비(非)엔비디아 가속기를 검토할 때의 질문이 **"우리 모델을 포팅할 수 있나?"에서 "우리가 쓰는 연산자 중 몇 개가 조용히 CPU로 떨어지나?"로 바뀐다.**
- 내일 회의에서 쓸 문장: "포팅 비용은 한 줄로 내려갔으니, 이제 PoC에서 볼 건 TFLOPs가 아니라 연산자 커버리지와 CPU 폴백 비율입니다."
- 실행 가능한 구성요소: `torch.profiler.profile(activities=[..., ProfilerActivity.PrivateUse1])` → `key_averages().table(sort_by="self_privateuse1_time_total")`로 디바이스에 안 올라간 연산자 찾기. 벤더에게 연산자 커버리지 표 요구. dynamic/symbolic shape 쓰는 모델(가변 시퀀스 길이)은 1차 릴리스 대상 아님을 먼저 확인.

## 설명할 메커니즘 (게이트 2)
**파이토치 디스패처(dispatcher)와 디바이스 키.** 독자가 오늘 처음 알게 될 원리:
- `torch.matmul`을 부르면 파이토치는 바로 계산하지 않고, (연산자, 디바이스 키) 쌍으로 등록된 커널을 찾아 넘긴다.
- CUDA의 해자는 드라이버가 아니라 **`cuda`라는 디바이스 키에 수천 개 ATen 연산자 커널이 전부 등록돼 있다는 사실**이다.
- 다른 칩에는 그 자리가 없어서, 그래프 컴파일러(XLA 등)로 모델을 통째로 잡아 넘기는 우회로를 썼다. 대가는 eager 모드 포기 — 브레이크포인트·print·파이썬 제어 흐름.
- `PrivateUse1`은 파이토치 커뮤니티가 외부 하드웨어용으로 **비워 둔 디바이스 키**다. TorchNeuron이 그 자리를 채워 `cpu`·`cuda` 옆에 `neuron`이 생겼다.
- **그런데 키를 얻는 것은 '배차'를 얻는 것이지 '커널'을 얻는 것이 아니다.** 연산자마다 구현이 따로 있어야 하고, 없으면 CPU로 떨어진다. 에러가 아니라 그냥 느려진다. ← 글의 반전 지점

## 출처 바깥의 사고 (가정, 예측 아님 + 근거)
커널이 **벤더 납품물이 아니라 패키지**가 되는 방향. 근거: Hugging Face `kernels` 라이브러리가 NKI 커널을 배포하고 Transformers v5가 attention·kernel을 모델 구현 전반에 표준화했다. 그렇다면 해자는 '누가 커널을 다 가졌나'에서 '누구 커널이 더 많이 설치되나'로 옮겨간다 — 가정이지 예측은 아님.
