# 토픽 팩트 카드 — 2026-10-05 (KST)

## 선정 토픽
**CVE-2026-61500 — Rejetto HFS 세션 쿠키 서명 키가 `Math.random()`에서 나왔고, 공개 하루 만에 실제 공격에 쓰였다**

## 선정 사유
- (a) 복수 출처 교차 확인 가능: The Register(2026-10-03), VulnCheck(Patrick Garrity LinkedIn), CVE 데이터베이스, 기술 분석글, HFS 릴리스 노트.
- (b) 평론 각도가 있음: "AI가 취약점을 찾았다"가 아니라 **모델이 한 일은 두 개의 '낮음' 등급 소견을 하나의 체인으로 이어붙인 것**이라는 재해석. 그리고 저자가 직접 Node로 검증 가능한 숫자가 있음(아래).
- (c) 한국 엔지니어 접점: Node/TypeScript 서버에서 `Math.random()`으로 id·토큰·키를 만드는 패턴은 아주 흔하다. SAST가 "insecure PRNG, 심각도 낮음"으로 올려 두고 몇 년씩 닫히지 않는 백로그 항목이기도 하다.
- 최근 중복 없음: Mythos라는 이름은 07-19·08-02·08-09에 언급됐지만 이 사건(HFS CVE)은 처음. 09-21 Plugin4Shell 이후 보안 토픽은 2주 공백.

## 기술 체인 (재현 가능한 수준으로)
1. **키 생성:** HFS가 기동할 때 `randomId(30)` 실행 → `Math.random().toString(36)`을 세 번 불러 이어 붙인 30자 문자열을 **Koa 세션 쿠키의 서명 키**로 영구 사용.
2. **출력 유출:** 인증이 필요 없는 `loginSrp1` 요청마다 서버가 `Math.random()`으로 만든 `sid`를 세션 쿠키에 담아 **클라이언트에게 돌려줌**. 1번과 **같은 PRNG 인스턴스**.
3. **상태 복원:** 인증 없는 `loginSrp1` 요청 **6회**로 연속된 출력 5개를 수집 → 버려진 하위 비트를 전수 탐색 → V8 `xorshift128+`의 128비트 내부 상태 복원 (Z3 SMT 솔버 사용). 이후 과거·미래 출력이 모두 예측 가능.
4. **키 역산:** 상태를 기동 시점까지 되감아 서명 키 후보 산출 → 서버가 실제로 보낸 쿠키의 HMAC와 맞춰 후보 확정.
5. **세션 위조:** `{ username: "admin" }` 세션 객체를 같은 키로 서명.
6. **RCE:** 관리자 권한으로 `set_config` 호출 → `server_code` 설정에 임의 JavaScript 주입 → 서버 프로세스 권한으로 실행.

## 저자 직접 검증 (이 세션에서 Node v22.22.0 / V8 12.4로 실행, 본문 중심축)
- `Math.random()` 결과에 2^52를 곱하면 **항상 정수**다 → 한 번의 호출이 노출하는 것은 정확히 **52비트**. (10만 회 전수 확인)
- 즉 64비트 상태 워드 중 **12비트만 버려진다** → 버려진 부분은 전수 탐색이 가능한 크기.
  ⚠ 2차 기술 분석글은 "11비트 / 2,048가지"로 적었으나, 직접 확인한 가수는 52비트(→12비트 / 4,096가지)다. **본문에서는 '한 번에 52비트가 보인다'는 검증된 사실만 쓰고 전수 탐색 가짓수는 단정하지 않는다.**
- `Math.random().toString(36).slice(2)`의 길이는 대개 11자(2만 회 중 14,175회), 10자 5,195회 → 세 번 이어 붙이면 30자를 넘겨 자르는 구조와 일치.
- **숫자 재해석:** 30자리 base36 문자열은 겉보기에 `30 × log2(36) ≈ 155.1비트`. 그런데 그 문자열을 만든 PRNG의 내부 상태는 **128비트**이고, 그 128비트는 로그인 응답 몇 개로 복원된다. 155비트처럼 보이는 키의 실제 안전성은 155비트도 128비트도 아니고, **관측 가능해진 순간 0**이다.

## 평론 각도 (본문 축)
1. **Mythos가 한 일은 '발견'이 아니라 '결합'이다.** ①서명 키를 `Math.random()`으로 만든다 → SAST가 매일 올리는 CWE-338, 보통 "심각도 낮음 / 악용 불가"로 닫힌다. ②로그인 엔드포인트가 세션 id를 돌려준다 → 그 자체로는 정상 동작. 두 소견은 각각 취약점이 아니다. **9.8은 둘을 이어 붙인 자리에서 나왔다.** 서로 다른 코드 경로에 흩어진 소견을 체인으로 보는 일은 정적 분석기가 구조적으로 못 하고, 사람은 시간이 없어서 안 한다.
2. **행위 주체는 사람이다 (09-13 규칙 7).** 헤드라인은 "앤트로픽의 모델이 찾았다"이지만, HFS 릴리스 노트의 크레딧은 "Zach Hanley of Horizon3.ai, in collaboration with Claude and Anthropic Research"다. 핸리는 Horizon3의 Chief Attack Engineer고, 문제를 고르고 방향을 잡고 익스플로잇까지 확인한 쪽이다.
3. **사정거리 긋기 (09-13 규칙 4).** "모델이 없었으면 못 찾았을 것"이라고 단정할 수 없다. 두 소견 모두 사람이 찾을 수 있는 것이고, 실제로 찾았을 수도 있다. **더 정확한 표현은, 이 체인을 '찾을 가치가 있는 것'으로 판단하는 비용이 내려갔다는 쪽이다.** 또 출처들은 익스플로잇이 공개 분석글에서 재구성된 것인지, 공격자가 독립적으로 만든 것인지는 밝히지 않았다.
4. **286 대 2.** 286건 중 실제 악용은 두 번째. 이 숫자는 양쪽으로 읽힌다 — 프로그램이 대체로 아무도 노리지 않는 것을 찾는다는 뜻일 수도, 악용 자체의 기저율이 원래 낮다는 뜻일 수도 있다. 어느 쪽인지 출처는 말하지 않는다.
5. **공격자 쪽 시계.** 공개 수요일(09-30) → 악용 목요일 저녁(10-01). 패치는 이미 나와 있었다.
6. **실행 가능한 마무리 (09-13 규칙 9):** `crypto.randomBytes`·`crypto.randomUUID`, 서명 키는 기동 시 생성하지 말고 환경변수·시크릿 저장소에서 주입, 인증 없는 엔드포인트가 난수 원본을 돌려주지 않게 할 것, 그리고 **"심각도 낮음 / 악용 불가"로 닫아 둔 백로그를 '짝이 있는지' 기준으로 다시 볼 것.**
