# 다운로드 폴더 정리 리포트

사람이 보고 있지 않아도 같은 결과가 나오도록, 순서를 여기에 고정한다.
이 문서가 기억하므로 매번 다시 설명하지 않는다.

## Phase 0 — 중복 실행 게이트
`out/report.md`가 이미 있으면 사용자에게 덮어쓸지 묻는다.
답을 받지 못하면 **아무것도 하지 않고 종료**한다.

## Phase 1 — 수집
`scanner` 에이전트에게 대상 폴더를 주고 `out/scan.json`을 만들게 한다.

**직접 폴더를 읽지 않는다.** 수집과 작성을 한 쪽이 다 하면 둘 다 대충 하게 된다.
역할을 나누는 이유가 이것이다.

## Phase 2 — 작성
`writer` 에이전트에게 `out/scan.json`만 주고 `out/report.md`를 쓰게 한다.
폴더를 다시 읽게 하지 않는다. 재료는 scan.json 하나다.

## Phase 3 — 검증
```bash
node scripts/check-report.mjs
```

- **종료코드 0** — 끝이다. 리포트 경로를 사용자에게 알린다.
- **종료코드 1** — 지적된 항목만 고쳐 Phase 2부터 다시 한다. **최대 2회.**
- 2회를 다 쓰고도 실패하면 리포트를 지우지 말고 남긴 채 **중단**한다.
  그리고 "실패한 채로 끝났다"고, 무엇이 걸렸는지와 함께 보고한다.

## 절대 규칙
1. 검증을 통과하지 못한 리포트를 "완료"라고 보고하지 않는다.
2. 게이트를 통과시키려고 `scripts/check-report.mjs`를 고치지 않는다.
3. Phase를 건너뛰지 않는다. 빨라 보여도 다음 실행에서 결과가 갈린다.
