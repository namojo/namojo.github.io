01 · 대상과 목표

누구를 위한 과정인가

책을 읽고 AI에 관심이 생겼지만, 써 보면 결과가 들쭉날쭉해 결국 손으로 고치고 있는 사람을 전제로 설계했습니다. 개발자가 아니어도 됩니다. 터미널은 명령을 붙여 넣는 창으로만 씁니다.

이 과정이 다루지 않는 것 프롬프트 기법, 에이전트 정의 파일을 손으로 쓰는 법, 나레이션·AI 이미지 생성. 앞의 둘은 한 번의 결과를 좋게 하는 방법이거나 3시간 안에 끝나지 않고, 마지막은 별도 API 키가 필요합니다. 이 과정은 반복되는 결과를 고르게 하는 구조를 보고, 만들고, 돌려 보는 데 집중합니다.

수료 시 할 수 있는 것

  1. 단일 에이전트와 멀티 에이전트의 차이를 컨텍스트 · 분업 · 검증 분리 · 비용으로 설명할 수 있다.
  2. 같은 과업의 두 결과물을 비교해, 차이가 중간 산출물과 검증자 분리에서 온다는 것을 파일로 짚을 수 있다.
  3. 하네스 폴더를 열어 CLAUDE.md · 에이전트 · 스킬 · 오케스트레이터가 각각 무슨 역할인지 말할 수 있다.
  4. 여섯 가지 아키텍처 패턴을 구분하고, 주어진 팀이 어떤 패턴을 섞었는지 판정할 수 있다.
  5. 내 업무를 반복 · 품질 요구 · 관여 인원으로 판정해, 하네스가 필요 없는 일도 가려낼 수 있다.
  6. “하네스 구성해줘”에 도메인 · 입력 · 산출물 · 품질 기준을 담아 팀을 만들고, 그 팀으로 결과물을 얻을 수 있다.
  7. 완성형 스킬(showreel)로 영상을 만들며, 판단은 스킬에 · 측정은 도구에 맡기는 구분을 내 하네스에 옮길 수 있다.
설계 의도 목표 1~5는 보는 눈, 6은 만들기, 7은 더 큰 하네스에서 배우기입니다. 조립은 플러그인에 맡기고, 그 대신 무엇이 만들어졌는지 읽어 내는 눈을 기르는 데 시간을 씁니다. 소재를 참가자가 직접 고른 작품(책·영화·행사·게임)으로 둔 것은, 결과물을 자기 것으로 느껴야 끝까지 점검하기 때문입니다.

02 · 전체 흐름

왜 이 순서인가

세 세션은 문제 → 원리 → 제작 → 확장으로 이어집니다.

  • 1북토크 — 문제에 이름 붙이기AI를 쓰는 일에서 맡기는 일로 넘어갈 때 무엇이 어려워지는지 말로 갖습니다. 실습은 없고, showreel로 소개할 작품 하나를 정해 둡니다.
  • 2대표 실습 — 원리를 결과물로 확인하기단일 vs 멀티 에이전트 개념 → 실습 키트의 제안서 A/B 비교 → 하네스의 네 원리와 필요 없는 경우 → 여섯 가지 패턴. 만들기 전에 좋은 것을 먼저 봅니다.
  • 3showreel 하네스 — 한 문장으로 짓고 돌리기세션 2에서 본 구조를 플러그인으로 만들고, 같은 눈(패턴 · 중간 산출물 · 검수 분리)으로 점검하고, HTML 릴을 뽑습니다.
  • +실제 영상 — 끝까지 커진 하네스하네스가 만든 조사표와 장면표를 showreel 스킬에 넘겨 MP4를 만들며, 오디오 우선 · 비평 반복 · 기계 검수를 내 하네스와 비교합니다.
세션 2를 먼저 두는 이유 한 번도 좋은 하네스를 보지 못한 사람에게 “하네스 구성해줘”를 시키면, 만들어진 파일 더미를 보고 판단할 기준이 없습니다. 세션 2에서 검증자가 따로 있다, 중간 산출물이 있다, 이 팀은 파이프라인 + 생성·검증이다를 먼저 확인해 둬야 세션 3에서 자기 팀을 점검할 수 있습니다.
영상 단계를 HTML 릴과 MP4 둘로 나눈 이유 showreel 스킬은 15초 영상도 30~50분이 걸립니다. 하네스만으로 MP4까지 가게 하면 세션 안에 아무 결과도 손에 쥐지 못하는 참가자가 생깁니다. 그래서 하네스는 브라우저에서 바로 재생되는 HTML 릴까지(15~20분), MP4는 완성형 스킬에 맡겨 시작만 세션 안에서 합니다. 두 결과를 나란히 놓으면 “같은 원리가 어디까지 커질 수 있는가”가 그대로 보입니다.

강사 노트 트랙 B를 당일에 다시 돌리지 마세요. 20~40분이 걸리고, 참가자마다 끝나는 시간이 달라 진행이 무너집니다. 이미 만들어진 결과를 읽는 것이 이 세션의 일입니다. 다시 돌리기는 키트 README에 집에서 할 과제로 넣어 뒀습니다.

5단계에서 A가 이기는 경우를 반드시 말해 주세요. 빠뜨리면 참가자는 “모든 일을 하네스로” 만들려 합니다. 판정기에서 L1이 나온 참가자에게 “그 결론도 정답”이라고 짚어 주면 좋습니다.

패턴은 외우게 하지 마세요. 파이프라인과 팬아웃의 차이(기다리는가), 팬아웃과 감독자의 차이(언제 나누는가) 두 가지만 확실히 하면 나머지는 그림으로 구분됩니다. 마지막에 “작품 소개 영상 팀이라면 어떤 모양일까”를 던져 세션 3으로 넘깁니다.

비교표나 패턴 판정이 교재 예시와 다르게 나옵니다
정상입니다. 예상 결과는 형태이지 정답이 아닙니다. 비교표는 B 쪽에 ID가 붙은 표·확약·수치가 있다는 방향만 맞으면 되고, 패턴 판정은 파이프라인과 생성·검증이 들어 있으면 됩니다. “계층적 위임”이라고 답하면 왜 아닌지(팀장이 다시 나눠 주지 않는다)를 함께 짚으세요.

가장 좋은 교보재입니다. 화면을 공유받아 “이 날짜가 조사표 어디에 있나요?”를 함께 찾고, “검수 담당이 이걸 왜 못 잡았을까”를 묻습니다. 그다음 /reel-studio 검수만 다시 또는 교재 7단계의 회고로 검수 규칙을 고치게 하면 하네스 개선까지 한 번에 경험합니다.
에이전트가 5명 넘게 만들어지거나, 검수 담당이 없습니다
프롬프트의 “4명 이내”, “분리해줘”가 빠졌을 가능성이 큽니다. 시간이 있으면 “검수 담당을 분리해서 다시 구성해줘”로 고치고, 없으면 백업 하네스로 넘어갑니다.
reel.html 이 빈 화면이거나 바로 끝납니다
장면의 시작·끝 초가 비었거나 겹친 경우가 많습니다. /reel-studio 검수만 다시를 시키면 검수 담당이 장면표와 대조해 원인을 짚고 담당자에게 넘깁니다. 세션 안에 안 풀리면 백업 하네스로 다시 돌리세요(10분).
작품 정보가 웹에 거의 없습니다 (사내 행사, 출간 전 도서)
정상 동작을 확인할 기회입니다. 조사 담당은 brief의 정보를 ‘사용자 제공’으로 쓰고 나머지는 확인 안 됨으로 남겨야 합니다. 지어낸 정보가 없다면 통과입니다. 영상이 단조로우면 brief의 ‘꼭 넣을 정보’를 채워 다시 돌리게 하세요.

시간이 어긋날 때의 우선순위

진행이 밀리면 아래 순서로 덜어 냅니다. 위에서부터 버리세요.

  1. Session 3 5단계(장면 고치기) → 생략
  2. Session 2 실행 모드 표 → 한 줄 언급 (패턴 카드와 퀴즈는 유지)
  3. Session 2 구성물 열기 5분 → 2분 (/agents와 다섯 명 표만)
  4. Session 3 생성 단계 → 전원 백업 하네스로 대체 (8분 → 2분)
  5. Session 1 독자 질문 10분 → 5분 (대담 본문은 유지)
끝까지 지켜야 할 세 지점 Session 2의 인벤토리 7분, Session 2의 패턴 퀴즈, 그리고 21:25의 영상 제작 시작입니다. 인벤토리가 빠지면 “하네스가 왜 나은가”의 답이 사라지고, 퀴즈가 빠지면 세션 3에서 자기 팀을 판정할 눈이 없고, 영상 시작이 늦어지면 참가자가 세미나가 끝난 밤 늦게까지 결과를 기다리게 됩니다.

수료 판정

  • 내 하네스(또는 백업 하네스)로 out/reel.html을 재생했다 (필수)
  • showreel 영상 제작을 시작했고 concept.md가 생겼다 (필수 · 완성은 세미나 뒤여도 됨)
  • 패턴 퀴즈를 풀고, 내 업무 하나를 단계 판정기로 판정했다 (권장)

체크박스 진행률은 각자 브라우저에만 저장되므로, 수료 확인은 재생 중인 릴 화면을 공유하는 방식으로 합니다.
