당일에 설치하면 그 시간이 실습에서 빠집니다. 전날까지 끝내 주세요. Windows 기준으로 썼고, 탭에서 macOS를 고르면 Mac 명령이 나옵니다.

Claude Code는 Claude Pro 이상 구독 계정으로 로그인합니다. 무료 계정으로는 실습이 되지 않습니다. 아직 없다면 claude.ai에서 가입하고 구독을 켜 두세요.

GPU나 고사양 컴퓨터는 필요 없습니다. 모델은 Claude 쪽에서 돌고, 내 노트북은 파일을 읽고 쓰는 일만 합니다.

사용량을 꽤 씁니다 멀티 에이전트는 담당자 수만큼 사용량이 듭니다. Pro 요금제라면 세미나 당일 낮에는 Claude를 아껴 써 두세요. 한도에 걸리면 그 자리에서 더 진행할 수 없습니다.

Windows에서 Claude Code는 Git과 함께 설치되는 Git Bash로 명령을 실행하므로 꼭 필요합니다. 이미 있다면 확인만 하고 넘어가세요.

PowerShell
winget install --id Git.Git -e --source winget

설치가 끝나면 PowerShell 창을 새로 열고 git --version으로 확인합니다.

터미널

버전이 나오면 끝입니다. 처음 실행하는 Mac이라면 개발자 도구 설치 창이 뜨는데, 설치를 누르고 기다리면 됩니다.

끝나면 PowerShell 창을 새로 열고 claude --version으로 확인합니다.

“claude 명령을 찾을 수 없습니다”가 나오면

설치 경로가 PATH에 등록되지 않은 경우입니다. 아래를 붙여 넣고 PowerShell 창을 다시 여세요.

PowerShell
$claudePath = "$env:USERPROFILE\.local\bin"
$userPath = [Environment]::GetEnvironmentVariable("Path", "User")
if ($userPath -notlike "*$claudePath*") {
    [Environment]::SetEnvironmentVariable("Path", "$userPath;$claudePath", "User")
}
터미널
curl -fsSL https://claude.ai/install.sh | bash

끝나면 터미널 창을 새로 열고 claude --version으로 확인합니다.

PowerShell · 터미널
claude

처음 실행하면 브라우저가 열립니다. 1단계의 Claude 계정으로 로그인하면 터미널에 입력창이 뜹니다. “안녕”이라고 한 번 걸어 보고 답이 오면 성공입니다. 아직 창을 닫지 마세요. 다음 단계에서 이 입력창을 씁니다.

『생존을 위한 최소한의 AI 교양』 — 다가오는 AI 시대의 변화를 뛰어넘기

지식 노동의 스푸트니크 쇼크에서 에이전트 시대의 생존 전략까지. 기술이 도구에서 충격이 되는 순간 무엇이 바뀌는지, 그 변화 앞에서 개인과 조직은 무엇을 준비해야 하는지 저자와 이야기합니다.

“모르면 당한다. 알면 부린다. 이제는 함께 실행한다.” 이 문장의 마지막 부분, 함께 실행한다를 이어지는 핸즈온에서 직접 해 봅니다.

이야기의 흐름

  • 1충격은 제도와 일의 방식을 바꾼다1957년 스푸트니크 쇼크는 위성 하나가 아니라 DARPA와 인터넷·GPS로 이어진 시스템의 변화였습니다. ChatGPT 쇼크와 에이전트 쇼크도 같은 구조입니다.
  • 2직업이 아니라 업무 단위가 바뀐다조사·초안·비교·승인·소통 같은 업무마다 AI가 맡는 부분과 사람이 맡는 부분이 갈리고, 역할이 섞이며 Builder가 등장합니다. 비엔지니어도 만들고, 엔지니어는 더 많이 설계하고 판단합니다.
  • 3모델 경쟁에서 실행 플랫폼 경쟁으로기술 확산의 병목은 모델이 아니라 사람·조직·습관입니다. 사람들은 최고의 모델보다 일을 끝내 주는 경험을 고릅니다.
  • 4개인의 생존 전략 — 에이전트 운용 능력질문을 잘하는 사람을 넘어 AI와 함께 결과를 만드는 사람이 강해집니다. 그리고 자동화가 깊어질수록 인간의 판단 지점이 성패를 가릅니다.

Session 2 · 20:00~20:50 · 50분

대표 실습 — 단일 에이전트 vs 멀티 에이전트, 그리고 하네스

개념을 짧게 본 뒤, 같은 과업을 두 방식으로 처리한 결과를 실습 키트로 뜯어봅니다. 마지막에 팀을 짜는 여섯 가지 모양을 익힙니다.

2-1. 단일 에이전트와 멀티 에이전트

에이전트는 목표를 받으면 스스로 파일을 읽고, 명령을 실행하고, 결과를 보고 다음 행동을 고르는 AI입니다. Claude Code가 그렇습니다. 이 에이전트 한 명에게 일을 통째로 맡길 수도 있고, 여러 명에게 나눠 맡길 수도 있습니다.

단일 에이전트

한 명이 하나의 대화 안에서 처음부터 끝까지

  • 빠르고 사용량이 적습니다. 문체가 한결같습니다.
  • 범위가 넓으면 깊이가 고르지 않고, 자기 실수를 자기가 못 봅니다.

멀티 에이전트

본체가 일을 나눠 맡기고 결과만 받는다

  • 분야마다 깊이가 고르고, 동시에 진행되며, 만든 쪽과 검사하는 쪽이 나뉩니다.
  • 사용량이 담당자 수만큼 늘고, 넘겨줄 양식을 미리 정해야 합니다.

여기서 쓰는 말 세 개만 알아 두세요.

  • 컨텍스트 — 에이전트가 지금 한꺼번에 보고 있는 작업 기억. 길어질수록 앞의 내용을 흐리게 다룹니다.
  • 서브에이전트 — 본체가 따로 띄우는 담당자. 깨끗한 컨텍스트에서 자기 몫만 하고 결과만 돌려줍니다. 담당자끼리는 대화하지 않습니다.
  • 오케스트레이터 — 누구에게 언제 어떤 순서로 맡길지 정하는 쪽. 하네스에서는 보통 스킬 파일 하나가 이 역할을 적어 둡니다.

그럼 하네스는 무엇인가 — 일의 세 단계

단계비유방식다음 달에도 같은 품질?
L1 · 혼자유능한 인턴 한 명지시 하나로 처음부터 끝까지 (단일 에이전트)사람이 매번 다시 설명
L2 · 팀그때그때 모은 전문가들나눠 맡기고 취합·검증 (멀티 에이전트)나누는 방법을 매번 다시 지시
L3 · 시스템직무기술서가 있는 팀역할·절차·규칙·검증을 파일로 남긴 멀티 에이전트 = 하네스같은 한 줄이면 됨

L1과 L3의 실행 명령은 둘 다 한 줄입니다. 차이는 명령의 길이가 아니라 그 한 줄이 기대고 있는 파일의 양입니다. 하네스는 이렇게 짜여 있습니다. 바로 다음에 여는 실습 키트가 이 구조입니다.

입력은 나라장터에 실제로 올라온 과업지시서 한 건입니다. 병원 진료기록을 연계하는 사업인데, 문서에는 FHIR, KCD-8, 심평원 EDI, 가명화 같은 말이 이름만 나옵니다. 보건의료 데이터를 모르는 사람이 이 문서로 제안서를 써야 합니다. 낯선 부서의 요청이나 처음 보는 규격을 받아 든 날과 같은 조건입니다.

트랙 A · 단일 에이전트트랙 B · 하네스(멀티 에이전트)
지시“과업지시서로 제안서를 작성해줘” 한 번전문가 5명이 순서대로·동시에 나눠 쓰고 검증
결과제안서A_단일패스.docx (3쪽)제안서B_하네스.docx (8쪽)

두 결과물과 트랙 B를 만든 팀이 키트에 이미 들어 있습니다. 트랙 B를 처음부터 돌리면 20~40분이 걸리므로, 오늘은 만들어진 결과를 뜯어보는 데 시간을 씁니다. Claude 입력창이 아니라 PowerShell(Mac은 터미널)에서 실행합니다. Claude가 떠 있다면 /exit로 먼저 나오세요.

curl.exe -L -o proposal-ab.zip https://namojo.github.io/aiguild/templates/proposal-ab.zip
Expand-Archive proposal-ab.zip -DestinationPath . -Force

PowerShell에서는 curl이 아니라 curl.exe로 써야 합니다.

터미널

curl -L -o proposal-ab.zip https://namojo.github.io/aiguild/templates/proposal-ab.zip
unzip -o proposal-ab.zip
cd proposal-ab && claude

Mac에서 pip 설치가 “externally-managed-environment” 오류를 냅니다
Homebrew로 깐 Python은 pip로 직접 설치하는 것을 막습니다. 수업 이후 A1단계처럼 brew install numpy pillow로 설치하세요. 그다음 preflight.py를 다시 실행해 numpy·Pillow 줄이 ✓인지 봅니다.
